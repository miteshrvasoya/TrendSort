# Architecture decisions

1. **Fastify + Zod + Drizzle** (not NestJS/Prisma): lighter, SQL-first, better pgvector support.
2. **Extra package `packages/db`** (schema, client, migrator) shared by API and workers, rather than putting Drizzle in `packages/shared`, which the browser also imports.
3. **Shared TS packages are consumed as source** (`main: src/index.ts`): `tsx` runs API/workers, Next uses `transpilePackages`. No build step for libs.
4. **Migrations are plain SQL** generated by drizzle-kit and applied by a tiny migrator (`packages/db/src/migrate.ts`); the first one enables `vector`.
5. **Release notes and tour steps are code-first** (`packages/shared`), synced into the DB at API start. This keeps "no feature without tour steps" reviewable in PRs and testable.
6. **Auth:** single sample admin from env, bcrypt + JWT in an httpOnly cookie. The cookie is host-scoped (not port-scoped), so web (:3000) and API (:4000) share it on localhost; Next middleware only checks presence, the API verifies. Change `ADMIN_PASSWORD`/`JWT_SECRET` before exposing anywhere. For hosted deployment, put web and API on one site (same registrable domain).
7. **Rs 0 budget:** `costPerCall` is typed as literal `0`; LLM is off by default (`LLM_ENABLED=false`). Paid APIs cannot be added without changing the type, by design.
8. **Scraping policy:** page-fetch connectors respect robots.txt (conservative if robots is unreachable), throttle per host, retry only 429/5xx, and never retry or bypass 401/403. Official APIs skip robots. Scraped sources are flagged lower confidence. Marketplace connectors that break terms of service ship disabled or manual-first; see `docs/PROPOSAL.md`.
9. **Sample data** is always `is_sample = true` with placeholder `algorithm_version = sample-0`; the UI labels it everywhere.
10. **Drizzle 0.36** pinned for drizzle-kit compatibility.
11. **Phase 1 entity matching is lexical** (tokens, containment, Jaccard 0.6). Single-word terms never create candidates. Embedding clustering waits for Phase 2.
12. **Candidates only from Movers & Shakers**, not every bestseller, to avoid flooding the trend list; they need approval before their keywords are tracked.
13. **Sample entities are excluded from live matching** so synthetic and real data never mix.
14. **Fixtures are hand-written approximations** of feed/page formats (the build sandbox blocked all external hosts), not recordings. First live runs may need parser adjustments; failures surface as run errors, not fake data.
15. **API enqueues runs via BullMQ** (Redis) rather than running connectors in-process, so "Run now" uses the same retry, DLQ and rate-limit path as scheduled jobs.
16. **Maths in Python, combination in TypeScript.** Python returns trend maths (momentum, sustainability, ratio, lag). Weighting, opportunity, stage and confidence are pure TS in `packages/shared`, so changing weights re-evaluates instantly from stored components without recomputing series.
17. **Missing inputs are excluded, never zero or neutral.** Opportunity reports its coverage; confidence includes it. Before v0.5 it therefore reflects demand and timing only.
18. **Google Trends compare requests** (one per keyword, all geos) so India and foreign share one scale; non-comparable series withhold stage, competition gap and lag window.
19. **Lead-lag uses smoothed raw series, not STL output** (STL edge effects distorted cross-correlation in tests). A trend's own lead-lag is displayed only if correlation >= 0.4 and never feeds the score; the category lag from the back-test does.
20. **Back-test dates are analyst estimates** from general knowledge, labelled as such everywhere, replaced per case by measurement when `measure-lag` finds a usable (>= 0.4) correlation.
21. **Gift deadlines are formulas, not forecasts**: import = festival - 84 days lead - 21 days runway; manufacture = - 45 - 21. Constants live in `packages/shared/src/gifts.ts` and are shown in the UI.
22. **Gift filters run in Node over a small set** (gift-vertical trends only), using shared pure helpers, so the same logic is unit-tested and no SQL duplicates it. Unclassified gifts (no profile) are excluded from attribute filters rather than guessed.
23. **Etsy search position is never a rank**: stored as `metrics.position`, `bsr` stays null, so it cannot inflate commercial proof. A missing key fails the run with a clear message and writes nothing.
24. **Price for gifts** comes from the gift profile; if absent, from a foreign list price converted at the latest ECB rate and labelled "not landed / not Indian retail". Margin waits for the unit-economics model (v0.5).
25. **Gift of the week** prefers real over sample gifts, then highest opportunity with an open import window; it is derived on read, not stored.
26. **Economics are pure shared functions** with hand-computed tests; the web runs them live and the API recomputes on save, so numbers cannot drift between screens.
27. **Duty/fee defaults are loudly indicative placeholders** by group (not per-HS-code claims), versioned and editable; scenarios store the version used. Nothing is presented as an official rate.
28. **Hybrid = import + local finishing** (e.g. import blanks, personalise in India), with no default price premium so it only wins when you say it earns one.
29. **Reviews are imported, not scraped**, and mined with a lexicon (Rs 0, no LLM). India listings come from Amazon.in top lists plus imports; the UI distinguishes "not checked" from "none found in scanned lists".
30. **Only saved fit attributes feed scores.** Heuristic inference is shown and marked, never silently scored. Same rule for scenarios: only a primary scenario feeds margin.
31. **Text matching helpers moved to `packages/shared/src/text.ts`** and are used by both workers and API.
32. **Verticals are validated JSON files** with in-app overrides stored separately (`verticals.overrides`), so seeding refreshes defaults without clobbering your edits, and Reset is trivial.
33. **Only config fields that change behaviour exist.** Per-vertical source weights were removed because nothing consumed them; they return when a second quantitative source does.
34. **Feature gap = foreign momentum x (3 - India presence)/3**, with India presence a category-level analyst estimate you can edit. I deliberately did not assert brand-by-brand competitor feature claims I cannot verify.
35. **Vertical India-fit notes are informational** (penalty 0) so config text cannot silently move scores; scoring still uses only saved fit attributes.
36. **Starter trends use names distinct from the sample trends** so tracking them never collides with demo data.
37. **Alerts fire on crossings with a per-day fingerprint**, so a metric that stays above a line does not spam; first sight above the line fires once.
38. **Prediction rule is deliberately simple** (India's share of the foreign peak keeps growing at its recent quarterly rate) so the tracker can state whether it beats "nothing changes". Live and back-test results are stored with an origin flag and never mixed; sample results are labelled as plumbing checks.
39. **Back-test hides the last 26 weeks of a trend's own history**, predicts from the truncated series and compares with the stage the full series shows; confidence used is the latest stored score's (a stated simplification).
40. **Workflow services (alerts, predictions, report gathering) live in `packages/db/src/services`** so the API and the workers share one implementation; pure logic stays in `packages/shared` and is unit-tested.
41. **Report email uses your own SMTP** (Rs 0); without it the report is download-only. PDF is generated with pdfkit (plain text layout, no browser needed).
42. **CSV export neutralises spreadsheet formulas** by prefixing cells that start with = + - @.
